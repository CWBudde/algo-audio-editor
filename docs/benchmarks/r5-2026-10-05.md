# R.5 kernel measurements — 2026-10-05

Implementation baseline: `c3d9180`. Measurements ran on Linux amd64,
Intel Core i7-1255U, with the module's Go 1.26.8 and Node 24.12.0.
These are observed local results, not portable timing guarantees.

## Analysis scheduling

The kernel batches existing work units under a 2 ms monotonic deadline.
It always advances at least one unit. A final indivisible unit, serialization,
binary copying, garbage collection and host scheduling can exceed that budget.
The worker continues to refill playback before/after calls and yield between
calls. Neither DSP order nor analysis resolution changes.

The native/V8 fixture is one hour of 48 kHz stereo audio assembled from a
repeated, varied immutable 16,384-frame block. Every selected frame and
spectrogram hop is analyzed; this fixture is not a codec-import test.
Spectrum uses a 2048-point Hann FFT with averaging 64. Spectrogram uses one
128×160 tile spanning the hour, including every FFT/4 hop. Reference mode
uses a deterministic clock to perform one primitive per call.

| Analysis | Single-unit JSON calls | Native budgeted calls | V8/WASM budgeted calls |
| --- | ---: | ---: | ---: |
| Statistics | 168,786 | 2,442 | 12,226 |
| Clipping | 168,751 | 1,722 | 6,215 |
| Selection spectrum | 130 | 2 | 8 |
| Spectrogram | 337,501 | 2,346 | 9,402 |

V8/WASM durations were 27.48 s, 13.61 s, 21.57 ms and 20.76 s respectively.
The largest observed statistics call was **21.99 ms**. The deadline is soft;
these measurements do not establish playback underrun acceptance. Pitch uses
the same scheduler with resumable 4096-work-unit steps, has deterministic
parity tests and remains separately opt-in for expensive hourly benchmarking.

[Analysis evidence and commands](r5-analysis-2026-10-05.txt) retain exact
counts, call durations and the fact that native reference timing overlapped
other checks. That evidence is explicitly a transcription of tool output.

## Actual FLAC import and production browser

The independent acceptance fixture contains **172,800,000 stereo frames**,
48 kHz, 24-bit PCM. Constant FLAC subframes change values at every 4096-frame
boundary; the two channels differ. A bounded native encoder writes the real
file with a complete STREAMINFO count and MD5. Compressed input is 869,076
bytes, but decoding retains 84,376 distinct blocks and 1,382,400,000 sample
bytes, plus 24,300,032 cached-peak bytes.

`TestFLACImportOneHour` verifies every decoded sample, initial clean history,
the shared memory ceiling and failed-checksum identity preservation. Native
and actual Node/WASM acceptance passed: import plus complete sample validation
took 5.75 s and 17.50 s respectively (fixture generation excluded).

The production Chromium test imports through the file picker, verifies both
channel waveforms and overview painting, reads actual PCM at many boundaries
and verifies exact storage/history dimensions. Import-to-painted-waveforms
took **12.519 s**, with 12.321 s in the import RPC. There is no new one-hour
timing threshold.

The same real browser document then completed statistics, clipping, spectrum
and spectrogram through the production `analysis.run` worker runner:

| Analysis | Actual JS→Go step calls | Main→worker requests | Duration | Maximum step |
| --- | ---: | ---: | ---: | ---: |
| Statistics | 6,348 | 3 | 13.628 s | 3.520 ms |
| Clipping | 3,215 | 3 | 6.799 s | 2.640 ms |
| Selection spectrum | 4 | 3 | 9.630 ms | 2.375 ms |
| Spectrogram | 5,095 | 3 | 10.910 s | 2.655 ms |

The three control messages are start, run and cancel. Test-only instrumentation
wraps `AAEKernel.call` inside the worker; counting main-thread messages alone
would miss the analysis steps. The browser fixture differs from the repeated
program used by native/V8 benchmarks, so their durations are not comparisons
of identical audio. [Browser evidence](r5-browser-2026-10-05.json) retains the
actual reports and is also attached to the Playwright test result.

Reproduce serially through `just`:

```sh
just test-flac-hour
just test-flac-hour-wasm
just flac-hour-fixture /tmp/aae-one-hour.flac
just test-flac-hour-browser /tmp/aae-one-hour.flac
just bench-analysis-hour
just bench-analysis-hour-wasm
```

The output fixture path must be new. Large codec acceptance is opt-in and
retains approximately 1.42 GB, keeping normal CI resource use bounded.

## Incremental history accounting

History now caches each state's immutable block inventory and updates a
copy-on-write ownership ledger for replacement, branching and pruning.
Storage queries merge only supplementary clipboard/candidate blocks.
Native race and actual V8/WASM tests compare totals and reference counts with
the independent `CountMemoryWithWindows` oracle, including randomized failed
transactions and clone isolation.

At-capacity one-hour cut/paste history benchmarks, three runs of ten iterations:

| Runtime | Baseline history | Incremental history |
| --- | ---: | ---: |
| Native | 11.75–19.28 ms | 1.10–1.65 ms |
| V8/WASM | 47.52–49.84 ms | 3.86–5.95 ms |

The baseline used the original history implementation through a temporary Go
overlay; source documents and operations were identical. Incremental history
used 1,740,784 B/op and 169 allocations, compared with 1,753,568 B/op and 153
allocations previously: fewer scans and slightly fewer bytes, with more small
allocations. Cached storage queries with an overlapping fractional clipboard
took 0.6–0.7 µs native and 2.3–4.0 µs WASM (192 B, two allocations).
Existing render allocation regressions remain mandatory and separate.

## Final validation and playback gate

Full native race and actual V8/WASM suites pass, including registry completeness,
busy policies, strict decoding, upstream cause preservation and bridge progress.
Go lint/vet, tidy, formatting, web/desktop typechecks, all 1,078 frontend tests,
production/native builds and existing asset budgets pass. The normal browser
suite passes all 146 cases; nine selected Electron cases cover analysis,
effects, processing, restoration, codec I/O and undo.

Native render, mono/stereo/eight-channel transport, resampled transport and
meter-render/copy benchmarks all report **0 B/op and 0 allocs/op** over 100
iterations. Actual WASM allocation regressions also pass.

The original ten-minute spectrogram playback gate was rerun serially against
the production build with its assertions unchanged. It passed in 4,240.255 ms,
observed 1,209 painted columns and partial progress, and measured zero
underruns with live meters. The whole test passed in 9.6 s, including setup and
the final playback check. This local pass is retained as new evidence;
Phase 15's historical discrepancy/profile work and full processing matrix
remain open.
