## Summary

Engineering quality rose a lot after the 2026-10-04 remediation:

- **Kernel:**
  - Panic recovery is in place.
  - A single 3 GiB storage owner checks every decoder before it allocates.
  - MP3, PCM8 and LUFS correctness are fixed.
  - Method dispatch goes through a registry.
  - History accounting is incremental.
- **DSP:** resampling, BS.1770 weighting, noise capture and repair context all come from upstream `algo-dsp`.
- **Frontend:** `App.tsx` shrank from 965 lines to 7. Playback no longer re-renders React.
- **CI:** CI is truthful, actions are SHA-pinned, and Pages and desktop releases ship only commits whose CI passed.

The problems now are **discipline and priorities**:

- **CI red on `main`.** CI on `main` has failed for six consecutive commits (`d1c8caf` to `5fbf343`). The commit bodies say the full checks and hooks were skipped on request. The git hooks are not installed locally, and `main` has no branch protection.
- **macOS test failures.** The kernel test suite fails on the maintainer's own OS because of a real write-root bug. CI tests only Linux, so the failure never shows there.
- **Effort spent on polish.** Recent effort went into polishing individual effect editors, while:
  - closing a browser tab silently loses all work;
  - File → New is disabled;
  - autosave does not exist;
  - the first release was gated on signed three-OS installers and a rewrite of Go's standard-library math for license wording.

## What is genuinely good

- **Architecture rules hold.** `process()` in the worklet only copies; it does not allocate, post messages or call WASM. Bulk data is binary. A grep for `math.Sin/Cos/Pow/Exp/Log` in non-test kernel code finds only peak RMS and response-axis encoding. Windows, STFT, resampling, BS.1770, true peak, dither, fades, restoration and time stretch all live upstream.
- **Correct real-time chain.**
  - The SPSC ring publishes only after the samples are written and counts underruns only before end of stream.
  - Its 64-bit split counters are protected by a sequence lock.
  - The playhead is derived from consumed document tags plus `getOutputTimestamp`.
  - Resampled playback keeps exact frame counts and drift-free integer-remainder position tags.
- **Kernel core.**
  - Every mutation is staged and then published.
  - `Timeline.Splice` handles the boundary stickiness of markers and regions.
  - Undo and save points are exact.
  - WAV chunk bounds avoid uint64 overflow.
  - Coverage is high: history 99.4%, audiobuf 97.7%, effects 91.2%, engine 88.9%.
  - Tests are race-clean, fuzzed, and use `AllocsPerRun` with no `time.Sleep`.
- **Metering follows the standards.** Integrated loudness uses the −10 LU relative gate. LRA uses the −70 LUFS absolute and −20 LU relative gates. The gated snapshot runs at 1 Hz on the control path, not in `Render`.
- **Latency compensation** discards the first latency of wet output, feeds zeros past the end, and keeps dry and unselected channels aligned.
- **Frontend.**
  - Playback position is driven imperatively and stale transport results are blocked by epoch guards.
  - Preview updates are coalesced, latest-only.
  - Eight dialogs load as lazy chunks.
  - The EQ handles are real `role="slider"` elements with `aria-valuetext`, keyboard menus and pointer capture.
  - A Go-AST protocol parity test compares the version, every method name and the payload field names.
- **Security.**
  - Electron runs with `contextIsolation` and `sandbox`, without `nodeIntegration`. Navigation and redirects are guarded.
  - Every IPC call checks the sender frame and origin.
  - File access uses one-shot UUID capabilities with `realpath`, `O_NOFOLLOW`, an `fstat` size cap and atomic `wx` writes.
  - A strict fuse set is verified after packaging.
  - Native writes use `os.Root` and no-replace links.
- **CI design.** Actions are SHA-pinned, default permissions are `contents: read`, and there is no `pull_request_target`. Pages deploys only after a green `workflow_run` for the exact SHA. A desktop release requires that its tag is on `main` and that CI passed. The WASM budget fails closed. E2E asserts on real PCM: there are no screenshot assertions, and 32 files check sample data.
- **Commit bodies** state candidly which checks ran and which were skipped.

## Findings — Go kernel

Verification run:
- `go vet` (native and js/wasm) is clean.
- `golangci-lint` reports 0 issues on engine, history, ops, audiobuf and `cmd/kernel`.
- `go test -race` passes for engine, history, audiobuf and ops.
- `go test ./...` **fails** in `automation` and `mcpserver` on macOS.

- **H — write-root check rejects symlinked locations** (`internal/automation/files.go:62,85-95`).
  - `NewFilePolicy` canonicalizes each root with `EvalSymlinks`, but `destination()` compares that against `filepath.Abs(path)`, which is never canonicalized.
  - On macOS `/tmp` resolves to `/private/tmp`, so `aae-mcp --allow-write /tmp` rejects `/tmp/x.wav`. `t.TempDir()` under `/var/folders` fails the same way.
  - Failing tests:
    - `TestCLIHundredFilesNormalizeFadeResampleFLAC`
    - `TestBatchFailureIsolationNoClobberPreflightAndCancellation`
    - `TestWritePolicyTraversalSymlinkNoClobberAndAtomicOverwrite`
    - `TestMCPCLIAndUIProtocolParity`
  - The check fails closed, so this is not a security hole, but it is a real product bug.
- **M — the render bridge has no panic recovery** (`cmd/kernel/main.go`: `render`, `copyMeters`, `takeData`).
  - Only `Call` recovers.
  - `RenderWithPositions` runs upstream effect streams and the resampler. A panic there kills the Go runtime and loses every document and its history.
- **M — a recovered panic leaves engine state unknown.** `CallWithData` resets only `bulkData` and `callInputBytes`. Jobs, preview sessions and transports are left as they were. This is suspected; no concrete corruption path was found.
- **M — the MP3 gapless parser rejects files FFmpeg accepts** (`engine/mp3.go:111`).
  - It rejects a LAME padding `< 529` (padding is a 12-bit field) and fails the whole import when the Xing frame count differs from the decoded count, as with stale headers on cut files.
  - Neither case has a test.
- **M — a zero-size WAV `data` chunk is read as "runs to EOF"** (`engine/wav.go:~58`). An empty file whose `data` chunk is followed by `LIST`/`cue ` imports those chunk bytes as audio.
- **M — long functions.**
  - `applyEdit` (`edits.go:44-215`, 171 lines) is a 12-case switch that mixes validation, memory reservation, operation construction and selection. Its paste branch repeats the storage arithmetic.
  - Other long functions: `startAnalysis` 163, `convertClipboard` 158, `decodeWAVTimeline` 139, `inspectWAV` 122, `exportDocument` 107, `decodeMP3` 107.
- **L:**
  - `startAnalysis` returns six raw upstream errors without the method prefix, and contains the message typo "must be20Hz..Nyquist and bounded65536frames".
  - A non-string params argument still becomes empty params in the bridge.
  - `cloneEditor` is an identity function.
  - `maxHistoryBytes` equals the whole `StorageLimit` until `SetLimits` narrows it.
  - `StagePush`/`ReplaceCurrent` clone the whole `owners` map and rebuild `BlockInventory()` on every push.
  - `sourceFormat` and similar values are still plain strings.
  - `memory` and `protocol` have no tests.
  - The parsers have few table-driven subtests (38 `t.Run` calls across 186 test functions).

## Findings — DSP and real-time path

The tests run (effects, process, and the engine's transport, resample, meter, spectrum, DynamicEQ and multiband tests) all pass. The @timing hardware gates were not run.

- **M — the ring is sized in frames, not seconds** (`audio-engine.ts:11`, `RING_CAPACITY_FRAMES = 8192`; `stream-pump.ts`, 10 ms pump).
  - That is 186 ms at 44.1 kHz, 85 ms at 96 kHz and **42.7 ms at 192 kHz**.
  - The same worker serves every RPC, so at 192 kHz any blocking call longer than about 30 ms underruns.
- **M — the effect-preview horizon is 16 ms** (`audio-engine.ts:16`, 768 frames at 48 kHz).
  - It is refilled by a 1 ms interval, which browsers clamp to 4 ms.
  - A preview update that cannot be applied in place (`engine/effects.go:113-125`) builds the new stream, the upstream chain and `Prime` inside one synchronous call. `withStreamRefill` refills only before and after that call.
  - Underruns are suspected on slower machines, longer impulse responses, or Go GC pauses.
- **M — meters and live spectrum lead the audio** (`meters.go:241-261`). `recordOutput` runs at render time, so peak hold and clip indicators fire about 170 ms plus device latency before the sound is heard. The playhead does not have this problem.
- **M — the selection spectrum samples only `averaging` windows** (`analysis.go:494`). With the UI default of 8, a ten-minute 48 kHz selection is represented by 16,384 of 28.8 M samples (0.06%). A hum burst between those windows does not appear.
- **M — hard selection edges and cut tails** (`effects/stream.go:152-237`).
  - Wet output is truncated at `selected.End`.
  - Dry switches to wet as a step: a +12 dB shelf on a selection that starts mid-signal clicks at the boundary.
  - Reverb and delay tails are lost.
- **M — preview diverges from Apply after a seek or a mid-selection start** (`stream.go:111-129`).
  - Effect state starts from zero, while Apply runs continuously from `selected.Start`.
  - A 500 ms compressor release or a 2 s reverb RT60 sounds different for seconds.
  - A loop inside the selection resets the state on every wrap.
- **M — structural updates switch abruptly** (`engine/effects.go:113-142`). A new `Stream` replaces the old one with zeroed state and no crossfade. `SetMix` steps once per 128-frame quantum with no ramp, which causes zipper noise.
- **L — response graphs use only 256 log-spaced points** (`effect-parameters.tsx:165`). A Q 30 notch at 1 kHz shows about −10 dB instead of −40 dB.
- **L — files with 3, 5 or 8 channels lose channels on stereo devices.** Web Audio falls back to discrete mixing for those counts (`audio-engine.ts:251-260`).
- **L — the clipboard 5.1 → stereo fold is cyclic** (`clipboard_convert.go:141-148`): centre goes only to the left channel and LFE leaks into the right.
- **L — playback failures look like a normal end.** An effect error, a non-finite sample or a resampler error stops playback, and the UI shows EOF (`transport.go:212-215`, `transport_resample.go`).
- **L — export dither defaults to off** (`lib/export-settings.ts:38`).
- **L — normalization has no output ceiling.** Peak normalization uses sample peak, and LUFS normalization has no peak limit (`normalize.go:247`).
- **L — `readPlanar` end-of-file race** (`ring-buffer.ts:211-216`): under 3 ms of playhead error at EOF.

## Findings — frontend

What was fixed since 10-04:
- `App.tsx` was split.
- Playback no longer re-renders the tree.
- `use-process` and `use-effects` share `job-runner.ts` for the candidate and lock logic.
- A protocol name parity test was added.

`waveform-view.tsx` shrank only from 1427 to 1322 lines.

- **H — `useAppController` is a god hook** (`hooks/use-app-controller.ts`). It is 751 lines with 17 `useState` calls and returns about 55 fields (lines 697-750). `<AppLayout controller={controller}>` therefore re-renders when any of them changes, including `paletteOpen`, `silenceValue`, `informationOpen` or `metersOpen`. Dialog state and playback orchestration live in one function.
- **H — `effects.response` requests are not coalesced** (`effect-parameters.tsx:155-186`).
  - Every `EffectCurve` and band graph starts its own debounced (20 ms) request on every `node.params` change.
  - Multiband and Dynamic EQ send N RPCs per knob tick. The kernel computes all of them, serialized with preview updates.
- **H — closing the browser tab loses all work.**
  - There is no `beforeunload` anywhere, and README confirms it ("Browser tabs do not yet have that native close flow").
  - File → New is disabled (`lib/commands.ts:416`).
- **M — `EffectParameters` holds effect-specific rules:**
  - filter order and oversampling
  - Moog Q clamps
  - `descriptor.id.startsWith("filter")`
  - It also infers EQ structure from parameter ids with `/freq|frequency/i` and `/gain/i`. A future effect with a makeup "gain" parameter would be drawn into the EQ-curve editing path.
- **M — unchecked response decoding** (`effect-parameters.tsx:171-177`).
  - `getFloat64` reads `count × 16` bytes without a length check.
  - A `RangeError` thrown in the fulfilment handler is not caught by `.then(a, b)`, so it becomes an unhandled rejection.
- **M — RPC result casts** (`kernel/client.ts:104-214`, `kernel-call.ts:24-66`, `process-runner.ts:45`, `analysis-runner.ts:10`, `live-spectrum-runner.ts:9`, `operation-chain.ts:119`). None are checked at runtime.
- **M — session scaffolding is duplicated.** `use-edit`, `use-history`, `use-document`, `use-process`, `use-effects` and `use-selection` each hand-write latest/mounted/epoch/`owns` logic.
- **M — spectral selection has two owners** (`waveform-view.tsx:154` and the controller). The view also holds about 15 `useState` calls for view preferences.
- **M — graph accessibility is uneven.**
  - `dynamics-graph.tsx:74` makes a `role="img"` focusable.
  - `filter-response-graph.tsx` has no keyboard path.
  - The `parametric-eq-graph` wheel handler is stored in a ref assigned during render.
  - Wheel over a handle captures dialog scrolling with no modifier.
- **M — tests.**
  - `graphic-eq-graph.tsx`, `filter-response-graph.tsx`, `kernel-call.ts`, `kernel.worker.ts`, `use-app-controller.ts` and `app-layout.tsx` have no colocated tests.
  - `parametric-eq-graph.test.tsx` asserts on the path `d` attribute instead of keyboard or wheel behaviour.
- **L:**
  - Hard-coded graph geometry (`BOTTOM = HEIGHT - 50`, width 640, `preserveAspectRatio="none"` stretching text).
  - Derived menu state is reset in an effect.
  - `ResizeObserver` guards are inconsistent.
  - `kernel-call.ts` special-cases `effects.response`.
  - `use-app-controller.ts:616` and `use-automation.ts:147-148` cast around nullability.

## Findings — security

No critical or high findings. Every Electron remediation from 10-04 still holds.

- **M — web assets sit outside ASAR integrity.** `electron-builder.yml` places `editor-web/dist` in `extraResources`. On a per-user Windows install, user-level malware could patch renderer JS and WASM without touching a signed binary. This needs same-user access.
- **M — Windows updater publisher not pinned** (suspected). There is no `publisherName`, so electron-updater relies on the `latest.yml` sha512 from the same release.
- **M — MCP memory can reach 8 × 3 GiB** (`mcpserver/server.go:23`, `memory/budget.go:8`). The budget is per engine, and a session can hold 8 engines.
- **L:**
  - UNC paths in argv reach `realpath` and can trigger an SMB connection before any user consent (Windows, suspected).
  - Desktop folder writes use `link()`, which fails on exFAT and SMB.
  - The write-root error message is confusing (see the kernel H finding).
  - `ReadFile` blocks forever on a FIFO.
  - The Pages build has no CSP.
  - The `app://` CSP lacks `frame-src`, `form-action` and `frame-ancestors`.
  - The IPC sender check is duplicated across modules.
  - There is no `govulncheck`, Dependabot or CodeQL.
  - Linux artifacts are unsigned.

## Decisions taken with the user (2026-10-08)

1. **License policy is property-based.** Allowed: OSI-approved, permissive, non-copyleft licenses with preserved attribution (MIT, BSD, Apache-2.0, ISC, 0BSD, Zlib, BlueOak, PSF, Unlicense, CC0, and the Go standard-library notices). Denied: GPL, LGPL, AGPL, MPL, SSPL and non-commercial terms. Accepted exceptions are reviewed and recorded. The Go math replacement is dropped.
2. **`v0.1.0` is a development release.** It ships the web build plus unsigned desktop artifacts. Signing and installed-update acceptance (Phase 19) gate 1.0.
3. **MCP completion (Phase 22) is deferred** until after `v0.1.0`.
4. **Phase 16's gate is replaced** by throughput and responsiveness gates plus a ±15% CI regression guard.
