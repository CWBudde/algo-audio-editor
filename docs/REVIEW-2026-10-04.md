# Code Review — 2026-10-04

Scope: the whole repository at `f8a35c2` (41 commits, about 75k lines). Three parallel reviews covered the Go/WASM kernel, the React frontend, and build/CI/Electron/docs. Each **critical** and **high** finding was spot-checked by hand before it went in here. The remediation work is tracked as **Phase R** in [PLAN.md](../PLAN.md).

Severity: **C** critical · **H** high · **M** medium · **L** low.

## Summary

The engineering *intent* is well above average. The render path allocates nothing, the ring buffer is careful, the hook tests target races, the Electron IPC is capability-based, Go coverage is about 89 %, and every sibling dependency is current. What pulls the score down is **verification discipline**, not cleverness:

- CI has **never passed** on `main`. Browser and Electron e2e have **never run in CI**, and PLAN.md claims they do.
- GitHub Pages deploys every commit regardless of the CI result.
- The kernel has **no panic recovery**. One panic in a decoder or a DSP call kills the Go runtime and loses every open document and its history.
- There are no consistent memory budgets. WAV has no decoded-size cap, while FLAC/AIFF/MP3 are capped at about 23 minutes of stereo.
- Structure is drifting: `Engine` is a god object, `App.tsx` (965 lines) and `WaveformView` (1427 lines) are too large, and `use-process` and `use-effects` are copy-paste of each other.
- PLAN.md has become a 154 KB lab notebook. Its pass/fail claims contradict each other.

## What is genuinely good

- **Real-time path.**
  - The render paths have zero allocations and are asserted with `AllocsPerRun`.
  - The playhead is derived from consumed frame tags plus `getOutputTimestamp`, so it doesn't drift.
  - The cursor is painted imperatively in `requestAnimationFrame` without React state.
- **Ring buffer.** A correct single-producer/single-consumer ring: samples are written before the index is published, wraparound is right on both sides, and underruns are only counted before end-of-stream.
- **Async correctness in the UI.** Epoch/token guards and latest-only coalescing are used consistently. The hook tests use deferred promises to force adversarial orderings.
- **Kernel core.** Edits commit atomically, undo/redo is exact (one hour, 100 steps), and coverage is 87–99 % in the core packages.
- **Electron.**
  - `contextIsolation`, `sandbox`, no `nodeIntegration`; navigation is locked.
  - Every IPC handler checks the sender frame and origin.
  - File access goes through one-shot capability ids with `realpath`/`O_NOFOLLOW`, a size cap and atomic writes.
  - The `app://` traversal guard is correct.
- **Rules 1, 3 and 4 hold.** There is no DSP in JS. The ABI version matches on both sides (18). Bulk data travels as transferables or through the SAB.
- **Dependencies.** `just check-deps` is green, and there are no `replace` directives or pseudo-versions.
- **Static checks.** `go vet` (native and js/wasm), golangci-lint, `tsc --noEmit` and `biome check` are clean; 907 Vitest tests pass.

## Findings — Go kernel (`packages/kernel`)

### Correctness

- **H — no top-level panic recovery.** `Engine.Call` promises it "never panics on bad input" (`internal/engine/engine.go:267-270`), but neither `CallWithData` (`engine.go:99`) nor the bridge (`cmd/kernel/main.go:113-139`) recovers. The only `recover()` calls are in `internal/process/builder.go:143,153`. A panic in go-mp3, flac, aiff or algo-dsp kills the runtime and loses all documents and history.
- **H — import size limits don't match.**
  - FLAC, AIFF and MP3 go through `validateDecodedFormat` (`codecs.go:62-66`), which caps them at `maxProcessOutputBytes`, 512 MiB (`process.go:14`). That is about 23 minutes of 48 kHz stereo, so a one-hour FLAC can't be opened.
  - WAV (`wav.go:137-208`) has no decoded-size cap at all, only the 2 GiB input limit (`cmd/kernel/main.go:35`). A 1.9 GiB 16-bit file decodes to 3.8 GiB of float32 plus the input copy, which exceeds the 4 GiB WASM memory and crashes with out-of-memory.
- **M — MP3 always opens as stereo** (`codecs.go:225-253`). go-mp3 always decodes to 2 channels, so a mono MP3 becomes two identical channels. Encoder delay and padding (LAME/Xing) aren't trimmed, so files gain leading silence.
- **M — 8-bit WAV silence isn't zero.** `wav_test.go:149` asserts that byte `128` decodes to `1/255`. The AIFF/FLAC path (`appendPCM`, `codecs.go:115`) uses symmetric scaling. 8-bit WAV therefore carries DC, and WAV↔FLAC/AIFF conversion is inconsistent. The test enshrines the bug.
- **M — loudness channel weights disagree.** `analysisWeights` (`analysis.go:565-584`) applies 5.1 weights (LFE = 0, surrounds = 1.41) for 5 and 6 channels, and statistics and meters use it (`meters.go:41`). The Normalizer uses unit weights (`process/normalize.go:36-37`). A 6-channel file normalized to −23 LUFS measures as something else.
- **M — the noise profile is biased low** (`process/restoration.go:214-219`). The first frame is centred at `ProfileStart`, so half of it is zeros. At the minimum profile length of `FFTSize/2` (`:88`), every frame is at most 50 % real audio.
- **M — generating at the cursor on some channels desyncs them** (`process/operation.go:166-176, 537-545`). The selected channels shift by the inserted length, the others are padded with silence at the end, and the timeline isn't spliced.
- **L:**
  - `normalize.go:333,353-358` is unreachable.
  - FLAC/AIFF export ignores short reads (`codecs.go:339`); the WAV path checks them (`wav.go:299`).
  - `analysis.go:154` dereferences `e.history` before the nil check at `:170`.

### Architecture (rule 6: missing DSP goes upstream)

- **M — resampler design is written here, three times.** Per-phase tap scaling, group-delay compensation, zero flushing and exact-length trimming appear in `engine/transport_resample.go:31-55`, `engine/clipboard_convert.go:47-56` and `process/resample.go:60-74`. `rateGCD` and the converted-frame-count helper are duplicated too (`process/resample.go:238,247`, `transport_resample.go:69,73`). algo-dsp's `resample` should provide a length-exact offline stream.
- **M — BS.1770 channel weighting is hand-rolled** (`analysis.go:565`). It belongs in `measure/loudness`.
- **M — noise-profile framing is driven locally**, one STFT frame at a time (`restoration.go:213-237`). `restoration.NoiseProfile` should own it.
- **L:**
  - float32→float64→float32 round trips just to call `vecmath.AddBlock` for a sum (`ops/operation.go:417-423`) or a 0.5 downmix (`process/operation.go:379-386`).
  - Crude 5-stop spectrogram colormaps (`analysis.go:586-602`).
  - No automated Go↔TS protocol parity check.
  - `decode` doesn't reject unknown fields (`engine.go:397-407`), so a misspelled optional parameter falls back to its default without any error.
  - A non-string params argument becomes empty params (`main.go:121`).

### Performance and memory

- **H — no one owns the worst-case memory.** The budgets below each fit on their own but add up to well over 4 GiB, and nothing reserves against the WASM limit:
  - the bridge copies the whole input into Go (`main.go:134`)
  - history is `max(512 MiB, 2×doc)` (`engine/history.go:29`)
  - each process candidate up to 512 MiB
  - paste-mix and clipboard conversion 512 MiB each
  - the impulse-response store 32 MiB
  - export pre-allocates the whole file (`wav.go:258`), and `takeData` copies it again
- **M — analysis does very little per call.**
  - Statistics and clipping process 1024 frames per `analysis.step` (`analysis.go:21,321`). For an hour of 48 kHz audio that is about 170k JSON round trips.
  - Spectrograms compute one FFT per call (`analysis.go:489-498`).
  - Process batches are limited to 4 steps (`process.go:18`).
- **M — every history push recounts all memory.** `prune` and `ReplaceCurrent` call `countBytes()`, which walks every block of every retained state, once per prune iteration (`history/history.go:116-119,179-194`). Undo pays it again (`engine/history.go:343`).
- **L:**
  - With `includeData`, each spectrogram column copies the whole 256 KiB tile (`analysis.go:129`).
  - A map literal is allocated per channel (`operation.go:188`).
  - The export inner loop branches on dither for every sample (`wav.go:303`, `codecs.go:342`).
  - FLAC export uses fixed prediction only: no LPC and no stereo decorrelation (`codecs.go:319`).

### Code quality

- **H — `Engine` is a god object.** It has 30 fields (`engine.go:35-67`) covering tone, document, transport, history, clipboard, process jobs, effects preview, impulse responses, meters, spectrum, analysis and a tile cache, all in one package of about 5k lines. The 160-line `dispatch` switch repeats the decode boilerplate for every method.
- **M — busy states are guarded by two hand-maintained allow-lists** (`process.go:31-53`, `effects.go:23`).
- **M — the error-wrapping convention is broken in places.**
  - Raw upstream errors are returned without a method prefix: `restoration.go:96,136,143,150,223,226,233` and `wav_metadata.go:434,462,509,542`.
  - `%v` is used instead of `%w`: `codecs.go:151`, `effects_ir.go:76`.
  - Messages are missing spaces: "must be20Hz..Nyquist" in `analysis.go:228,244`.
- **M — string-typed dispatch everywhere** ("fade-in", "analyzing", "ready", …), for example `operation.go:42,105,261`.
- **L:**
  - `cloneEditor` is an identity function (`engine/history.go:23`).
  - Dense one-line struct literals and conditions are hard to review (`operation.go:103,219`, `restoration.go:60,88`).

### Tests

- **M — fuzzing gaps.** The WAV fuzz seeds have no LIST/INFO, adtl, cue or bext chunks, and export isn't fuzzed. The INFO walk (`wav_metadata.go:255-262`) relies on validation done earlier in the same function. The fuzz target uses `&Engine{}` rather than `New()` (`wav_test.go:396`).
- **M — missing cases:** mono MP3, multichannel loudness consistency, one-hour FLAC import, behaviour near the memory limit.

### Robustness against malformed files

- **M — too strict for real-world files** (`wav.go:37-49`). It rejects:
  - a RIFF size larger than the file (truncated recordings)
  - RIFF or data sizes of 0 or `0xFFFFFFFF` (streaming writers)
  - a final odd-length chunk with no pad byte
  - RF64
- **L:** ID3 skipping trusts the declared tag size (bounded by the input) and doesn't resync if no MP3 frame follows.

## Findings — Frontend (`apps/editor-web`, `packages/protocol`)

### Architecture rules

- **M — rule 2 is broken in the worklet.** `readPlanar` (`audio/ring-buffer.ts:180-241`) runs inside `process()` and allocates heap BigInts every quantum:
  - `Atomics.add/load` on a `BigInt64Array` (`181, 212, 226, 239`)
  - `BigInt(...)` conversions (`214-233`)
  - the `positions[...]` read (`232`)
- **M — protocol mirror mismatches.**
  - Go's `ProcessJobResult.Candidate` is a pointer and can be `null`, but TS types it as required (`packages/protocol/src/index.ts:356`). `App.tsx:299-310` already treats it as optional.
  - Go's `DocumentInfoResult.Format` can be `""`, but the TS union excludes it (`index.ts:82`).
- **M — the bulk-method list is hardcoded twice** (`kernel/kernel-call.ts:30-41`, `kernel/stream-pump.ts:16-25`). Adding a binary method in one place but not the other silently drops its data.
- **M — `decodePeaks` runs twice per request:** once in the worker, where the result is discarded (`kernel-call.ts:84`), and again on the main thread (`hooks/use-peaks.ts:139`).
- **L — effect meters are polled as JSON every 50 ms** (`use-effects.ts:391-402`), even though a SAB meter channel exists.

### Correctness

- **H — selection state lives in a mutable object inside `useMemo`** (`hooks/use-selection.ts:57-87`). It is mutated in place (`108-119`, `184-212`) and renders are forced with `useReducer`. React doesn't promise to keep memoized values, so this is the core of selection handling resting on an implementation detail.
- **M — worklet nodes leak.** On a channel-count change the old node is only disconnected (`audio/audio-engine.ts:239`), and its processor always returns `true` (`audio/playback-worklet.ts:42`). Orphaned processors keep running on the audio thread. This happens on every mono↔stereo preview (`App.tsx:300-307`).
- **M — `play()` isn't serialized.** It awaits the transport fence but never becomes it (`audio-engine.ts:80`). `ring.reset` (`:86`) and the transport RPCs therefore race a later `seek`/`stop`; only generation checks keep this correct.
- **M — kernel edits can be ignored by the UI.** The results of `edit.apply` (`use-edit.ts`), `history.jump`/undo/redo (`use-history.ts:254`) and `process.commit` (`use-process.ts:417`) are dropped when the identity check fails, but the kernel has already mutated the document. The UI keeps a stale `documentId`.
- **M — engine lifetime under StrictMode.** It is created in `useMemo` (`App.tsx:72`) and disposed in an effect cleanup (`121-127`). It works only because `dispose()` happens to reset fields.
- **L:**
  - The `audiblePosition` seqlock only checks `epoch`, not the history slots that are written as two 32-bit stores (`ring-buffer.ts:208-209, 263, 275`). The comment claims more than the code guarantees.
  - Magic counter indices instead of the `COUNTER` constants (`232-233, 252`).
  - `runSpectrum` guesses its request id from `nextId` (`kernel/client.ts:205`).

### Component design

- **H — oversized components.**
  - `App.tsx` (965 lines) holds about 20 `useState` calls and wires 14 hooks by hand. It writes refs during render (`85`, `211`) and has a force-render hack (`109`).
  - `WaveformView` (1427 lines) owns view state, pointer input, follow mode, rulers, markers/regions, spectral UI and scroll sync.
- **M — two sources of truth for the selection.** App's `selected` (`App.tsx:87`) is synced by a layout effect (`waveform-view.tsx:311`), and App also reads `waveformView.current.selectionState()` imperatively in about 15 places.
- **M — `use-process` and `use-effects` are copy-paste.**
  - `deferred()` is defined twice with different implementations (`use-process.ts:47`, `use-effects.ts:50`).
  - `owns`/`update`/`report`/`finish` are nearly identical.
  - Document locking and the commit flow are the same (`process:398-418` vs `effects:449-468`).
- **M — cancellation boilerplate is rewritten six times.** The pattern (latest ref, `mounted` ref, epoch, token, `active()`) appears in `use-edit`, `use-history`, `use-document`, `use-process`, `use-effects` and `use-selection`.
- **M — duplication inside `App.tsx`.** `playPreview`/`stopPreview` are written twice (`254-279` vs `293-330`), and the "is a modal open" check is repeated five times.
- **L:**
  - Channel masks are computed two ways: `(1 << n) - 1` and `2 ** n - 1`.
  - `useMemo(fullRange, [info])` should depend on `info.frames` (`waveform-view.tsx:298`).
  - `COUNTER_BYTES` reserves 10 slots but only 9 are used.

### Performance

- **H — re-render storm during playback.**
  - `setStats` runs every 200 ms (`App.tsx:661`), re-rendering the whole tree just to feed a hidden About dialog.
  - `resolveCommands` builds a new ~70-entry array every render (`use-commands.ts:43`).
  - Inline object props, e.g. `App.tsx:828`.
- **H (UX) — the waveform blanks on every pan, zoom or follow step.** `use-peaks.ts:98` clears the snapshot and `PeakCanvas` draws `null` (`waveform-view.tsx:203,217`) until the kernel replies.
- **M — follow mode calls `setState` every animation frame** (`waveform-view.tsx:453-475`), so each frame re-renders `WaveformView` and sends a new `peaks.get` per lane.
- **M — bundle and WASM size.**
  - One 702 KB JS chunk (216 KB gzipped). The ">500 kB" warning has been noted since Phase 3 and never addressed.
  - `kernel.wasm` is 11.0 MB (2.79 MB gzipped), with no `wasm-opt`.
  - The WASM is served unhashed from `public/`, so Pages can pair a stale kernel with new JS.

### Type safety

- **M — RPC results are cast without validation** (`client.ts:104`, `kernel-call.ts:18-24`). The wire `params` are `unknown` (`messages.ts:16`) and cast back in the worker (`kernel.worker.ts:137`).
- **L:**
  - `` `effects.${string}` `` in `CommandId` (`lib/commands.ts:70`) accepts typoed ids.
  - `as Parameters<…>` cast in the process command table (`App.tsx:618`).

### Accessibility and UX

- **M — the waveform canvas is `role="img"`** (`waveform-view.tsx:241`), yet it is the main selection surface. There is no keyboard way to place the cursor or select on it.
- **M — the selection edge handles step ±1 frame** (`waveform-view.tsx:1247-1268`). There is no acceleration and no `role="slider"`/`aria-valuenow`, and every keypress fires a `selection.set` RPC plus a seek.

### Tests

- **M — `App.test.tsx` mocks 12 modules** (`31-169`), so it only tests wiring.
- **M — `e2e/process-benchmark.spec.ts` (917 lines) monkeypatches `worker.postMessage` and parses the internal wire format inline** (around `376-420`). Any change to `messages.ts` breaks it. It also asserts machine-dependent wall-clock times.
- **L — no cross-thread producer/consumer test for the ring buffer.**
- **L — 56 % of Vitest's 33.7 s is spent rebuilding jsdom 69 times**; consider `environment` per file or worker isolation tuning.
